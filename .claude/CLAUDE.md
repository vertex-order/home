## What this repo is

The [Vertex Order](https://vertex-order.github.io) org landing page — one
page linking out to every franchise list, plus a shared FAQ. The lightest
repo in the org: no series data, no platform icons, no floating nav.

`data/{games,movies,books}.js` each assign a plain `window.*_FRANCHISES`
array — `{ title, href?, by?, firstPublished? }`, `href` omitted for a
placeholder. `data/faq.js` holds the FAQ copy (`window.FAQ_ITEMS`).
`page.dc.html` (the entry page) renders all of it.

This repo **owns** `page.dc.html` and the `data/` files. It **vendors**
`support.js`, `_ds/`, `FAQ.dc.html`, and `ThemeToggle.dc.html` from
`vertex-order/kit` — never hand-edit those; `sync.toml` is the manifest and
`check-vendored.yml` enforces it. Full-checkout tooling: `just sync` /
`sync-update`; in a design tool the vendored files are just the
last-synced committed copies. `components.js` stays generated — don't
hand-edit it either.

The FAQ's `a` array supports plain-string paragraphs and
`{ parts: [...] }` paragraphs, where a part is `{ text }`, `{ em: text }`,
or `{ text, url }` for a link.

## Regenerating components.js

`components.js` (next to `page.dc.html` and the sibling `*.dc.html` files —
currently `FAQ.dc.html` and `ThemeToggle.dc.html`) is a **derived build
artifact** — it inlines every sibling `*.dc.html` component (all except the
entry page, `page.dc.html`). Never hand-edit `components.js`.

### When it actually matters

`page.dc.html` loads `components.js` **only when opened over `file://`**
(double-clicked off disk), where the runtime's `fetch()` for sibling
`*.dc.html` is blocked:

```html
<script>
  if (location.protocol === 'file:') {
    document.write('<script src="./components.js"><\/script>');
  }
</script>
```

Over **http(s)** — GitHub Pages, `just serve`, **and the Claude Design
preview** — the tag is skipped and the runtime fetches each `*.dc.html`
live. So inside a design tool, editing `page.dc.html` shows up in the
preview immediately; a stale `components.js` **cannot** cause wrong
rendering there. `FAQ.dc.html` and `ThemeToggle.dc.html` are vendored, so
you shouldn't be editing them here at all — change them in kit instead.

You therefore do **not** need to hand-regenerate `components.js` for your
work to render correctly in a preview. Regenerate it to keep the committed
artifact honest (below). If you skip it, the repo's pre-commit hook and CI
(`.github/workflows/check-generated.yml`) regenerate it, and CI fails the PR
until it matches. **If the user opens the page over `file://` and refreshes,
though, they see a stale bundle until you regenerate.**

### How to regenerate

**Full repo checkout** (has `scripts/`, `justfile`, `.githooks/`):

```sh
just bundle-components                 # or: just build
python3 scripts/bundle-components.py   # same thing, if `just` isn't installed
```

**Design tool / flat working directory** (just the `site/` files as your
root, plus this `CLAUDE.md`; no `scripts/`, no shell) — reproduce the
script's exact output by hand so it stays diff-clean. Read every sibling
`*.dc.html` except `page.dc.html`, then overwrite `components.js` with:

```js
// AUTO-GENERATED by scripts/bundle-components.py — DO NOT EDIT BY HAND.
//
// Inlines every sibling *.dc.html component (all except page.dc.html) so
// <dc-import> resolves without a fetch(), which browsers block on file://
// origins. The *.dc.html files are the single source of truth.
//
// page.dc.html loads this ONLY on file:// (see its inline guard). Over
// http(s) the runtime fetches each *.dc.html live. Regenerated by the
// pre-commit hook and `just build`.
(function () {
  var C = {
  "./ComponentA.dc.html": "<full source of ComponentA.dc.html as a JSON string>",
  "./ComponentB.dc.html": "<full source of ComponentB.dc.html as a JSON string>"
  };
  window.__resourceBlobs = window.__resourceBlobs || {};
  for (var k in C) {
    if (!window.__resourceBlobs[k]) {
      window.__resourceBlobs[k] = new Blob([C[k]], { type: "text/html" });
    }
  }
})();
```

Rules for the by-hand version:

- One `C` entry per sibling `*.dc.html` file, **excluding `page.dc.html`**,
  in sorted filename order.
- Key is `"./" + filename`. Value is the file's full source,
  JSON-stringified (this is what `json.dumps(..., indent=2)` produces —
  2-space indented, `ensure_ascii=False`).
- Keep the IIFE + `var C` + loop shape and the `window.__resourceBlobs`
  global exactly. `support.js` reads that global; a different name or shape
  silently no-ops.
- The header comment at the top of the current `components.js` is the
  authoritative spec — match it.
